# Шпаргалка: снятый запрос → код CLI

Когда ты снял запрос из Network (через `read_network_requests` или пользователь дал `Copy as cURL`), разбери его на части и перенеси в код команды CLI. Ничего не додумывай — переноси ровно то, что видел.

## Что вытащить из запроса

| Часть cURL / записи Network | Куда в CLI |
|-----------------------------|------------|
| URL (`https://api.сервис/v1/orders?limit=20`) | базовый URL + путь endpoint'а; query-параметры → флаги команды |
| Метод (`GET`/`POST`/`PUT`/`DELETE`) | тип операции команды |
| Заголовок `Authorization: Bearer ...` / `Cookie: ...` | **авторизация** — значение в `.env`, в код подставляется из окружения |
| Прочие заголовки (`X-CSRF-Token`, `Content-Type`, `User-Agent`) | часто обязательны — сервис отбивает запрос без них; перенеси как есть |
| Тело (`--data '{...}'`) | параметры команды; поля тела → аргументы/флаги |
| Ответ (JSON) | структура вывода; из неё берёшь нужные поля для `--json` |

## Порядок

1. **Сначала повтори запрос «один в один».** Убедись, что с теми же заголовками и телом сервер отвечает так же, как в браузере. Только потом обобщай в команду с параметрами.
2. **Вынеси секреты.** Всё, что похоже на токен/ключ/сессию, — в `.env` (`SERVICE_TOKEN=...`), в коде читается из окружения. В `.env.example` добавь строку-плейсхолдер.
3. **Не тащи лишние заголовки вслепую, но и не выкидывай нужные.** Если сомневаешься — оставь заголовок; сервисы часто требуют `User-Agent`, `Referer`, `X-Requested-With`.
4. **Параметризуй только то, что реально меняется** (id, лимит, страница, фильтр). Остальное — константы в коде.
5. **Ошибки.** Посмотри, как сервис отвечает на плохой запрос (401/403/429/5xx). Раздели retryable (повторить — таймаут, 429, 5xx) и non-retryable (401/403 — чинить токен/права): пусть CLI показывает понятную ошибку, а не падает молча.

## Грабли

- **Динамические заголовки.** `X-CSRF-Token` и подобное могут генерироваться на каждый запрос/сессию — тогда их надо не хардкодить, а получать (из cookie, из HTML-страницы, из первого запроса).
- **Cookie-сессия vs Bearer-токен.** Если авторизация на cookie — токен протухает; заложи перелогин. Если Bearer — часто есть refresh-endpoint.
- **Точный формат тела.** `application/json` ≠ `application/x-www-form-urlencoded` ≠ `multipart/form-data`. Отправляй тело в том же формате, что видел, — иначе сервис не поймёт.
